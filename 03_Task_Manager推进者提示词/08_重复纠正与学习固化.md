# 用户重复纠正 / 希望以后不要再犯｜V1.9

```text
【Task Manager｜重复纠正与学习固化】

我现在指出的问题希望系统以后更难再犯：

[写问题 / 规则 / 截图]

你不要只说“记住了”。

执行：

1. Capture Learning Event。
2. 你可以建议一个 pattern alias / rule key。
3. 你不能决定 canonical_pattern_id。
4. `resolve-learning-pattern` 必须把 alias / symptom 解析到机器权威 Canonical Pattern。
5. recurrence_count 由机器累计，不能由你填写。

升级策略必须是：

第 1 次：
→ Project Fix

第 2 次：
→ Reusable Candidate
→ Root Cause Review
→ 不要自动变 Guard

第 3 次仍复发：
→ Prompt-only FAILED
→ 读取 Canonical Pattern Policy
→ 能机器强制：Guard / Contract Test / Tool Constraint
→ 稳定多步 SOP：Skill
→ 否则：Template / Prompt Rule

如果进入 Skill：

→ 实现
→ Trusted Validation Receipt
→ Promotion Gateway
→ 自动 register-skill
→ SKILL_REGISTRY.status=PRODUCTION
→ Template Sync

你不能把“Skill 文件存在”当成已经 Production。

后续真实 Dispatch 必须：
→ resolve-skills
→ 真正加载 Skill
→ trusted loaded_skill_ids
→ record-skill-usage
→ record-skill-effectiveness

只有跨项目真实复用并记录 Effectiveness，才算学习闭环完成。
```

## V1.10 Candidate Merge / Skill Evidence

未知 Pattern 不要因为换一句话就永久新建多个 Candidate：

```text
NEW_PATTERN_CANDIDATE
→ Candidate Dedup
→ Experience Recorder Merge Proposal
→ pattern-merge-gateway
```

如果最终 Promote 为 Skill：

```text
Validated Content Hash
→ Production Registry
→ resolve-skills Hash Guard
→ LOADED
→ trusted used_skill_ids
→ USED
→ Cross-project Reuse
→ Independent Effectiveness
```

不能把：

```text
LOADED
```

直接写成：

```text
REUSED / EFFECTIVE
```
