
# 用户意见 / 截图 / 体验问题

## 普通反馈

```text
【用户反馈给 Task Manager】

这是用户反馈，不是让你亲自改代码。

反馈：
[文字 / 截图]

期望：
[可选]

优先级：
[如果我没有写 P0，你按 Stage / Defect 规则判断]

请：
1. 记录 User Feedback；
2. 对照 Stage Contract；
3. 分类 Stage P0 / Defect P0 / P1 / P2/P3 / Product Backlog / Future；
4. 判断是否重排当前主线；
5. 需要代码修改 → Dispatch Gateway 派 Builder；你自己不要改；
6. 需要验证 → Risk-driven QA；
7. 普通执行问题不要抛回给我；
8. Continuation Guard 不允许你处理完反馈后“顺便停下”；如果当前 P0 仍未完成，继续 next_action。

【Learning Capture】
如果这条反馈是：
- 我再次提醒以前说过的规则；
- 我说“以后都这样”；
- 同样的问题已经重复出现；
- 说明模板 / Prompt / Workflow 有系统性缺口；

立即创建 Learning Event。

同一治理要求：
第 1 次 Capture + Project Fix；
第 2 次 Reusable Candidate；
第 3 次 Prompt-only 仍失败 → Guard / Contract Test / Tool Constraint Candidate。

你只能 Capture / Request Promotion，不能直接改 authoritative Governance / production template。

先告诉我：
- 你把它分到什么优先级；
- 是否改变主线；
- 是否创建 Learning Event；
然后继续推进。
```

## 用户明确 P0

```text
【用户明确 P0】

下面问题由我明确指定为 P0：
[问题 / 截图]

不得自行降级。

请：
- 重排 Priority；
- 你自己不要改业务代码；
- Dispatch Gateway 派正确角色；
- Fix Attempt Fingerprint；
- Retry 新 Dispatch；
- 高不确定性失败触发 Diversity / Senior Expert；
- 达到 Fix Budget 才 Human Gate；
- Continuation Guard 确保未完成前不自行停；
- 如果这是对旧规则的重复纠正，同时创建 Learning Event 并升级固化层级。
```
