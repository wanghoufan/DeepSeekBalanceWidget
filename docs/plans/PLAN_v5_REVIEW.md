# PLAN_v5 审核报告

审核对象：`PLAN_v5.md`  
审核日期：2026-07-31  
结论：方案整体合理，可以作为 UI 增强迭代执行；但建议先修正按钮语义、峰值状态表述、时间基准和托盘资源管理等问题。

## 1. 官方信息核对

DeepSeek 官方价格页目前确实写明：峰谷定价“即将采用”，高峰时段定义为北京时间每日 9:00–12:00 和 14:00–18:00，并注明具体时间以正式通知为准。[官方价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

因此本功能应定位为“预计高峰时段指示”，不能宣称它代表当前账户的实时计费状态，也不能据此推断某次请求一定按高峰价格计费。

## 2. 已合理的设计

- 修复 `ApplyMiniMode` 强制重置右下角的位置 bug；
- 默认角落增加右下、左下和记忆选项；
- 高峰判断抽成纯服务并增加单元测试；
- 高峰状态独立使用 60 秒定时器，不依赖余额轮询；
- 托盘 tooltip 和图标同步更新；
- 保留关闭仅隐藏、托盘恢复和单实例设计；
- 没有改动余额解析、网络、DPAPI 和配置原子写等稳定部分。

## 3. 必须修正的问题

### 3.1 “关闭”和“收进任务栏”行为重复

两个按钮都执行 `Hide()`，都常驻托盘，用户无法区分其价值。建议二选一：

- 删除“收进任务栏”，关闭按钮明确命名为“隐藏到托盘”；或
- 保留两个按钮，但必须有不同语义，例如“关闭”关闭整个程序、“收进托盘”仅隐藏。

当前 v5 明确规定关闭不退出，因此更推荐删除重复按钮。

此外，“放进任务栏”并不准确。该实现实际是 Windows 系统托盘（通知区域），建议所有 UI 文案改成“收进托盘”或“隐藏到托盘”。

### 3.2 “缩小”按钮实际是迷你模式

“完整卡片 ⇄ 迷你胶囊”不是传统意义的最小化。建议按钮 tooltip 和无障碍名称使用：

- “切换迷你模式”；
- “展开完整卡片”；

而不是“缩小”，避免用户误以为窗口会进入任务栏。

### 3.3 高峰状态必须标注为预计/参考

当前文案使用“高峰/非高峰”，容易让用户理解为 API 已返回的真实计费状态。建议统一使用：

- “预计高峰时段”；
- “预计非高峰时段”；
- 或“峰值时段参考”。

在 tooltip、卡片和托盘菜单中都要保持一致，并在设置或关于信息中说明“官方策略尚待正式通知”。

### 3.4 时间基准不能只依赖本地时间

方案推荐“本地时间”，但官方定义明确是北京时间。用户系统时区变化、远程桌面、旅行或虚拟机环境都会导致错误判断。

建议默认使用：

```csharp
TimeZoneInfo.FindSystemTimeZoneById("China Standard Time")
```

以北京时间转换后再计算；或者增加“北京时间/系统本地时间”设置。若坚持本地时间，UI 必须显示当前使用的时区。

### 3.5 “跨整点即时切换”与 60 秒轮询矛盾

60 秒 `DispatcherTimer` 最多可能延迟约 59 秒才切换，不能称为即时。并且系统睡眠、定时器漂移和窗口线程阻塞会进一步延迟。

建议：

- 每次 Tick 都使用当前时间重新计算，不累加时间；
- 切换时计算下一个边界并安排一次性 Timer；
- 从睡眠恢复、系统时区变化和设置保存后立即重算；
- 验收标准改为“边界后最多 60 秒内切换”，或者将定时精度提高到 1 秒。

## 4. 托盘图标与 tooltip 风险

### 4.1 必须释放旧图标资源

运行时生成 `System.Drawing.Bitmap` / `Icon` 时，每次高峰状态切换都要释放旧对象，否则长期运行会造成 GDI 句柄泄漏。

建议：

- `TrayIconService` 保存当前 `Icon`；
- 替换前 Dispose 旧 Icon 和 Bitmap；
- 应用退出时 Dispose 当前 Icon、NotifyIcon 和菜单；
- 用 `using` 包裹临时 Bitmap。

### 4.2 tooltip 长度与实时性

Windows `NotifyIcon.Text` 有长度限制，不能只按“63 字符内”口头约束，应实现统一裁剪函数，并处理设置过长文本时的异常。建议保留最重要的信息：

```text
余额 ¥110.00 | -¥2.50 | 预计非高峰
```

余额刷新成功、变动变化、高峰边界切换和配置变更时都应刷新 tooltip；网络失败时应显示“余额未知，最后成功时间 …”，不要继续显示看起来像实时的数据。

### 4.3 图标颜色不应是唯一状态

红/绿对色觉障碍用户不够友好。tooltip 和托盘菜单必须同时显示文字；可增加不同形状或叠加小点/标记。图标绘制应验证 100% 和高 DPI 下可辨认。

## 5. UI 行为边界

### 5.1 置顶状态必须持久化并同步

标题栏按钮切换 `Topmost` 后，应立即更新：

- 当前窗口属性；
- `AppConfig.IsAlwaysOnTop`；
- 设置窗口中的复选框；
- 托盘菜单中的勾选状态（若有）。

否则重启后会恢复旧状态，或者设置窗口显示过期值。

### 5.2 迷你模式改变尺寸后要重新检查屏幕边界

删除 `ResetPosition()` 是正确的，但卡片高度变化后，窗口可能部分移出屏幕。建议：

- 保持当前锚点；
- 尺寸变化后执行工作区边界 Clamp；
- 不要把自由拖动位置强制改成右下角；
- 用户拖动后的坐标仍需保存。

### 5.3 默认角落的 `Remember` 语义要完整

如果没有历史坐标，`Remember` 应有明确回退策略，建议回退到当前主屏幕右下角。多显示器情况下应记录显示器设备标识或至少验证保存坐标是否仍在可见工作区。

## 6. 配置与高峰区间

- `PeakHourRanges` 建议存为列表而非固定“两段”，方便官方以后增加时段；
- 校验 `StartHour`/`EndHour` 为 0–24 的边界语义，避免 24 点无法表达；
- 当前 `Start<End` 不支持跨午夜区间，需在文档中明确这是有意限制；
- 配置损坏或区间非法时回退到官方默认值，并提示用户；
- `ShowPeakIndicator=false` 应只隐藏 UI，不影响内部计算和 tooltip（除非用户另有设置）；
- 设置变更后立即刷新卡片、胶囊、tooltip 和图标，不等待下一次 60 秒 Tick。

## 7. 测试补充

除 `PeakHourCalculatorTests` 外建议增加手工或自动验收：

- 北京时间与系统时区不一致时的判断；
- 9:00、12:00、14:00、18:00 边界；
- 系统睡眠后恢复；
- 修改峰值区间后立即生效；
- 60 秒 Timer 延迟和跨整点切换；
- 长时间反复切换图标无 GDI 句柄持续增长；
- tooltip 超长文本裁剪；
- 余额网络失败后 tooltip 不显示过期“实时”数据；
- 迷你模式切换不重置位置且不出屏；
- 置顶按钮、设置窗口和托盘菜单状态同步；
- 关闭/隐藏/托盘退出的区别；
- 高峰状态只显示参考信息，不触发余额告警。

## 8. 推荐修改后的执行顺序

1. 先改按钮命名和行为定义，删除重复的“收进任务栏”或让其与关闭有明确差异。
2. 实现 `PeakHourCalculator`，默认使用北京时间，并覆盖边界测试。
3. 加入高峰参考徽标与独立刷新调度，处理睡眠恢复和设置即时刷新。
4. 修复迷你模式尺寸变化后的边界 Clamp 和默认角落回退。
5. 实现托盘 tooltip 裁剪、状态同步和旧 Icon/Bitmap Dispose。
6. 增加设置项和配置迁移/非法值回退。
7. 完成 UI、托盘、生命周期和 Mock sequence 回归测试。

## 9. 最终结论

PLAN_v5 不需要推翻，主要是一次合理的 UI 增强迭代。进入实现前必须处理：

1. 任务栏/托盘命名与两个隐藏按钮的重复语义；
2. 峰值状态改成“预计/参考”而非真实计费状态；
3. 使用北京时间而非无条件使用系统本地时间；
4. 修正 60 秒定时器与“即时切换”的矛盾；
5. 释放动态生成的托盘图标资源；
6. 明确迷你模式后的边界和 Remember 回退策略。

处理后，v5 可以安全进入编码和回归验证。
